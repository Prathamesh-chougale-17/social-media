# Session User Data Fix - Complete Solution

## Problem

Comments were showing "Anonymous" even when users were signed in, and duplicate likes were possible due to userId mismatches.

### Root Cause Analysis

1. **better-auth Session Structure**: When a user signs in with Google OAuth, better-auth stores the session cookie with an **encrypted/encoded userId** (e.g., `jAggSQrfr7sKN0KnD96oSpeC5XCzc5Wh...`)

2. **Database Mismatch**: The user document in MongoDB's "user" collection has:
   - `_id`: MongoDB ObjectId (generated by MongoDB)
   - `id`: better-auth user ID (should match session userId, but might be missing in some cases)
   - `name`: User's display name
   - `email`: User's email
   - `image`: User's profile picture URL

3. **The Issue**: The code was trying to query `db.collection("user").findOne({ id: userId })` but:
   - Some user documents might be missing the `id` field
   - Even if present, querying the database on every comment is inefficient
   - The session cookie already contains the user's name and image!

## Solution

### ✅ Step 1: Extract User Data from Session (Not Database)

Updated `trpc/init.ts` to extract **name** and **image** from the better-auth session cookie:

```typescript
export interface Context {
  userId?: string;
  userName?: string;
  userImage?: string | null; // ✅ Added
}

const getUserImage = (s: any) => {
  if (!s || typeof s !== "object") return undefined;
  return s?.user?.image ?? s?.image ?? undefined;
};

const userImage = getUserImage(session);
return { userId, userName, userImage };
```

### ✅ Step 2: Pass User Data to createComment

Updated `lib/db/queries/interactions.ts` to accept `userImage` parameter:

```typescript
export async function createComment(
  videoId: string, 
  userId: string, 
  content: string, 
  authorName?: string, 
  userImage?: string | null  // ✅ Added
) {
  // Use provided session data (fast & reliable)
  let userName = authorName;
  let avatar = userImage;
  
  // Fallback: try database only if session data missing
  if (!userName) {
    const user = await db.collection("user").findOne({ id: userId });
    if (user) {
      userName = user.name;
      avatar = user.image;
    }
  }
  
  const doc = {
    videoId,
    userId,
    content,
    authorName: userName || "Anonymous",
    userName: userName || "Anonymous",
    userImage: avatar || null,
    createdAt: new Date(),
  };
  
  await db.collection(COMMENTS_COLLECTION).insertOne(doc);
  return doc;
}
```

### ✅ Step 3: Update tRPC Router

Updated `trpc/routers/interactions.ts` to pass all user data:

```typescript
createComment: protectedProcedure
  .input(z.object({ 
    videoId: z.string(), 
    content: z.string().min(1).max(2000) 
  }))
  .mutation(async ({ input, ctx }) => {
    const userId = ctx.userId!;
    const authorName = ctx.userName;      // ✅ From session
    const userImage = ctx.userImage;      // ✅ From session
    
    const comment = await createComment(
      input.videoId, 
      userId, 
      input.content, 
      authorName,  // ✅ Pass it
      userImage    // ✅ Pass it
    );
    
    return comment;
  }),
```

### ✅ Likes Are Single-Time Only

The MongoDB unique index on `(videoId, userId)` prevents duplicate likes:

```javascript
db.collection("likes").createIndex(
  { videoId: 1, userId: 1 }, 
  { unique: true }
);
```

If a user tries to like twice, MongoDB returns error code `11000`, which we catch and return `null`.

## Performance Benefits

- **No database query** needed for every comment (uses session data)
- **Single database write** operation
- **Instant user data** availability from session cookie
- **Fallback protection** if session data is missing

## Why This Works

1. **Session Cookie Contains Everything**: better-auth stores `user.name` and `user.image` in the session cookie
2. **No Race Conditions**: User data is available immediately from the request
3. **Database Fallback**: Still queries DB if session data is missing (backward compatibility)
4. **Type Safety**: All user data flows through tRPC's type-safe context
